## 3. 人工验收脚本

### 3.1 Windows Narrator

1. 启动本地应用和 Windows Narrator，不使用鼠标进入“今日”；
2. 通过跳转链接进入主要内容，确认只朗读一个页面主标题；
3. 依次进入学习、证据、收件箱、更多、目标与行动、设置；
4. 确认当前导航、加载、普通状态、错误和紧急错误能按视觉顺序理解，不重复或漏读；
5. 在设置页确认输入框名称、常驻说明、无效邮箱和保存结果能够关联；
6. 记录浏览器、Narrator 版本、阻断问题、非阻断问题和是否接受。

### 3.2 Windows 实际高对比度

1. 开启 Windows 高对比度主题，以常用浏览器依次进入今日、学习、证据、收件箱和设置；
2. 只使用键盘确认当前导航、焦点、按钮、链接、表单边框、禁用状态和紧急／普通状态可区分；
3. 检查内容没有因系统色覆盖而消失，状态也没有只依赖颜色表达；
4. 记录 Windows 版本、浏览器版本、所用主题、阻断问题、非阻断问题和是否接受。

### 3.3 连续两小时使用

1. 使用实际每天约两小时的学习节奏，完成诊断／学习／证据／收件箱中的真实只读或本地任务；
2. 每 30 分钟记录文字疲劳、页面密度、当前位置辨识、误把完成当掌握的风险和移动／桌面切换；
3. 两小时结束后记录必须调整、可以后续调整和可接受不调整的项目；
4. 只有项目所有者明确接受后，才把三项人工验收从“待确认”改为“通过”。

## 4. 调整记录

7F 没有增加依赖，以下调整均为验收暴露的最小前端修复：

1. 834px 平板的学习任务操作区在 200% 文本下横向溢出。窄桌面／平板断点将操作区改为
   单列网格，并允许操作按钮换行，保留原业务行为。
2. 干净数据库下，准备度和就业实验页面会显示完整能力范围或长输入值，WebKit 原生控件的
   固有宽度会把表单网格撑宽，834px 平板的合成快照说明也会挤出双列网格。为应用壳内带
   直接表单控件的标签统一补充收缩边界，将控件约束为容器宽度，在标签内保留 6px 焦点轮廓
   余量后裁掉原生内部溢出，并在不超过 1080px 时把准备度网格改为单列；没有缩短选项或
   输入值，也没有更改提交或 API 契约。
3. 200% 文本下固定像素侧栏会使导航和底部边界说明拥挤；直接按 `rem` 扩张又会挤压
   834px 平板正文。侧栏改为以 `30vw` 为流体上限、以原设计宽度为封顶的网格列，桌面、
   平板和 WebKit 复验均无横向溢出。

验收工具同时等待页面网络稳定后再切页、在逐页检查后恢复根字号，并把多浏览器总编排等待
上限从 120 秒提高到 600 秒。重放到包含 6C 的主线后，两条跨 11 页／18 次导航的穷举旅程
使用 60 秒总测试上限，单断言仍保持 5 秒；产品运行边界没有放宽。受控加载态解除路由时会
等待全部并发回调结束，避免测试编排与请求继续执行竞态；重复导航先等待网络稳定，再检查
标题与溢出，防止错过水合后请求并在下一次切页时由 WebKit 取消。该修复没有过滤页面错误。
WebKit 的 skip link 使用程序化聚焦验证，因为其键盘 Tab 行为与 Chromium 不同；Chromium
仍验证真实 Tab 键入口。
