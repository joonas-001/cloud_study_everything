# 云奕学初版视觉方向

> 状态：方向 A 组合方案已在 7E 收敛为设计令牌与无障碍基线；仍不是最终品牌规范
> 提案日期：2026-07-27
> 最近决定：2026-08-14 已授权并实施 7E，保持零新增依赖
> 适用阶段：本地单用户验证
> 不包含：Logo、商标、公开宣传资产和最终品牌规范

## 1. 方向名称

**静水深流**

“云”代表知识来源、连接和持续变化；“奕”表达推演、秩序与逐步精进。视觉不强调炫技式的“AI 感”，而应让用户感到安静、清晰、可信，适合每天长时间学习。

这是一项可修改的初版方向。后续应根据真实使用体验、可读性测试和功能密度调整，而不是为了保持视觉一致性牺牲学习效率。

项目所有者已确认现有前端需要在第七里程碑进行全站体验与信息架构重设计。“静水深流”
作为低刺激色彩和长时间使用原则的可修改基础，不构成最终品牌规范。方向 A“证据工作台”
用于全局骨架，方向 B 的专注布局和方向 C 的紧凑状态列表只用于适合的局部页面。详细范围、
信息架构和阶段见
[`milestone-7-frontend-redesign.md`](milestone-7-frontend-redesign.md)，7A 审计与可比较方向稿见
[`milestone-7a-experience-baseline.md`](milestone-7a-experience-baseline.md)，7E 令牌与组件契约见
[`milestone-7e-design-system.md`](milestone-7e-design-system.md)。7E 保持零新增依赖，未安装、
执行或复制外部设计技能；7F 仍须单独确认，实际体验验证可以继续调整令牌和组件。

## 2. 核心原则

### 2.1 证据优先

界面首先展示目标、完成标准、来源、评估证据和下一步行动。装饰元素不得压过学习信息。

### 2.2 克制而不冷漠

整体保持低噪声、高可读性，用少量温暖色提示进展和重要节点，避免纯工具界面的疏离感。

### 2.3 进度不等于掌握

完成进度和掌握证据必须使用不同的视觉表达。不能只用一个百分比、奖杯或连续学习天数暗示用户已经掌握能力。

### 2.4 变化可追溯

学习计划、来源和评估发生变化时，界面应突出“发生了什么、为什么变化、谁确认了变化”，而不是静默替换内容。

### 2.5 长时间使用友好

控制对比度、色彩数量和动效频率。阅读、编程和复盘页面应优先降低视觉疲劳。

## 3. 色彩系统

初版采用自然、低饱和的“云灰 + 深墨 + 青黛 + 暖金”体系。

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| Cloud 50 | `#F6F8F7` | 页面背景、低层级区域 |
| Paper 0 | `#FFFFFF` | 主内容表面 |
| Ink 900 | `#17212B` | 主文字、关键标题 |
| Ink 600 | `#53616D` | 次要说明、元数据 |
| Line 200 | `#D9E0E2` | 边框、分隔线 |
| Teal 700 | `#27656A` | 主操作、当前学习路径 |
| Teal 100 | `#DCEBEC` | 选中态和轻量提示背景 |
| Gold 600 | `#A96F24` | 证据、复核和重要提醒 |
| Gold 100 | `#F5E8D3` | 证据摘要背景 |
| Red 700 | `#A13D3D` | 错误、阻断和危险操作 |
| Green 700 | `#2F6B4F` | 已通过验证，不表示无限范围的“完全掌握” |

颜色不能成为传达状态的唯一方式。状态同时需要文字、图标或结构差异。

## 4. 排版

- 界面正文优先使用本地系统中文无衬线字体，避免首版本地验证依赖外部字体服务；
- 数字、代码、时间复杂度和版本号使用清晰的等宽字体；
- 标题通过字号、间距和字重建立层级，不大量使用全大写、超粗字或装饰字体；
- 正文建议保持舒适行高，长篇学习内容限制阅读行宽；
- 中英文混排时保留稳定的标点、数字和代码样式。

建议字体栈：

```css
font-family:
  Inter, "Noto Sans SC", "Microsoft YaHei", system-ui, -apple-system, sans-serif;
```

首版不从网络加载 Inter 或 Noto Sans SC；只有用户本机已安装时才使用。

## 5. 布局与组件语言

### 5.1 布局

- 7B 已采用统一应用外壳，桌面端使用左侧主导航，移动端使用底部导航；
- 一级区域为“今日、学习、证据、目标与行动、收件箱、设置”，其中收件箱与设置同级；
- 复杂学习工作区可在应用外壳内采用“任务路径 + 当前任务 + 证据或来源”的候选布局；
- 简单页面保持单一主列，避免为填满屏幕制造无意义卡片；
- 移动端按“当前任务 → 完成标准 → 证据 → 来源”顺序折叠；
- 重要操作靠近其影响对象，避免把所有操作集中到固定工具栏。

### 5.2 卡片与边界

- 使用轻边框和层级间距区分区域，谨慎使用大面积阴影；
- 圆角适中，不采用过度柔软、玩具化的视觉；
- 信息密集区域优先使用列表、表格和时间线，而不是把每项内容都包装成卡片。

### 5.3 掌握证据

掌握状态建议拆分展示：

- 理解；
- 操作；
- 迁移；
- 作品；
- 保持；
- 纠错。

每项状态都应能展开查看评估标准、最近证据、复核时间和仍存在的缺口。

### 5.4 来源

来源组件应显示：

- 标题和发布机构；
- 原始链接；
- 发布日期或版本；
- 检索日期；
- 证据强度；
- 冲突或待复核标记。

### 5.5 AI 状态

AI 生成、用户确认、系统校验和外部来源内容需要可区分，但不依赖夸张的渐变或机器人形象。建议使用明确标签和来源说明。

## 6. 动效

- 动效只用于解释状态变化、保持空间连续性或提示异步进度；
- 默认时长短且可被用户减少；
- 不使用持续漂浮、闪烁背景或无意义粒子动画；
- 加载状态应说明正在执行的工作，例如“正在校验来源”，不能只显示无限旋转图标；
- 遵守 `prefers-reduced-motion`。

## 7. 无障碍基线

- 正文和关键控件满足 WCAG AA 对比度目标；
- 全部交互可使用键盘完成；
- 焦点状态清晰且不可被移除；
- 表单错误与对应字段建立程序化关联；
- 图表和颜色状态提供文本替代；
- 不用倒计时、动效或声音强迫用户行动；
- 桌面、平板和移动尺寸均需验证阅读和操作顺序。

## 8. 暂不采用的方向

初版不采用：

- 高饱和紫蓝渐变作为大面积“AI”视觉；
- 游戏化金币、连续签到压力或虚假的掌握庆祝；
- 玻璃拟态叠层造成的低对比度；
- 大量营销式口号占据学习工作区；
- 未经验证就用绿色勾选表示“完全掌握”；
- 依赖外部网络字体才能正常呈现的排版。

## 9. 后续验证

完整应用视觉方向前，应至少验证：

1. 首页、诊断访谈、学习任务和证据详情四种页面的信息层级；
2. 桌面、平板和移动尺寸；
3. 空状态、加载状态、错误状态和外部 AI 关闭状态；
4. 键盘导航、焦点顺序、文本缩放和减少动效；
5. 用户连续学习约 2 小时时的阅读疲劳；
6. “完成进度”与“掌握证据”是否容易混淆。

验证结果可以改变本提案。每次重大调整应记录原因、影响范围和日期。
