## 1. 目标与边界

7E 将已有页面收敛到同一套语义令牌和交互状态，不改变页面信息架构、后端契约、证据等级、
技能包、部署或第六里程碑环境。设计系统服务于长时间学习和证据辨识，不把流程完成、绿色
状态或单项 Runner 结果包装成整体掌握。

## 2. 令牌层

`apps/web/src/app/design-tokens.css` 是令牌事实来源，按以下角色组织：

| 类别 | 令牌 | 用途 |
| --- | --- | --- |
| 文字 | `--color-text*`、`--font-*`、`--line-height-*` | 标题、正文、次要说明、代码和阅读行高 |
| 表面 | `--color-canvas*`、`--color-surface*` | 页面、面板、弱化区和禁用控件 |
| 交互 | `--color-action*`、`--color-focus`、`--control-size` | 链接、按钮、焦点和最小控件高度 |
| 状态 | `--color-accent*`、`--color-danger*`、`--color-success*`、`--color-warning*` | 强调、错误、成功与警告；不能单独传达含义 |
| 几何 | `--space-*`、`--radius-*`、`--shadow-*` | 间距、边界和低噪声层级 |
| 动效 | `--duration-*`、`--ease-standard` | 短时反馈；减少动效时统一降级 |

现有 `--ink`、`--muted`、`--line`、`--paper`、`--deep`、`--mist` 等变量只映射到语义令牌，
用于渐进兼容，不再定义独立颜色来源。

## 3. 组件契约

- `StatusMessage` 必须同时提供可见文字、非颜色标记和 live-region 语义；错误默认断言式播报，
  普通警告礼貌播报，只有会立即影响操作的恢复或协议异常使用断言式警告；
- 表单使用原生 `label` 和约束验证；常驻说明通过 `aria-describedby` 关联。未来若增加自定义
  字段错误，必须同时设置 `aria-invalid` 并关联可见错误文本；
- 加载状态使用 `role=status`、`aria-live=polite` 和 `aria-busy=true`，不能只显示动画点；
- 状态标签、证据等级和待办始终显示文字。颜色、进度条和图形只能作为冗余提示；
- 全部按钮、输入与选择控件以 44 CSS px 为基线；键盘焦点使用 3 px 实色轮廓和外圈阴影；
- 表格、时间线、空态、代码输出和详情摘要使用共享排版、边界和溢出规则。

## 4. 对比度与适配

令牌对比度以主表面 `#fbfcfb` 为背景计算：正文 15.25:1、次要文字 6.17:1、操作 7.59:1、
强调 6.31:1、危险 7.58:1、成功 6.84:1、警告 6.44:1、焦点 4.72:1。E2E 会重新计算正文、
次要文字和操作令牌并要求至少 4.5:1。

`prefers-contrast: more` 提高次要文字和边界强度；`forced-colors: active` 保留按钮、状态和
当前导航的系统边界；`prefers-reduced-motion: reduce` 把动画与过渡降到近零时长。页面网格
子项统一允许收缩，桌面与移动测试同时覆盖有效缩放和真实根字号 200% 放大后的横向溢出。
