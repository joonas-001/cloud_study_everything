## 3. 现有信息架构

### 3.1 页面与目标架构映射

| 当前路由 | 当前职责 | 目标一级区域 | 主要问题 |
| --- | --- | --- | --- |
| `/` | 产品介绍、里程碑卡片、进入各功能 | 今日 | 营销式 Hero 占据默认首页，不能直接回答“现在做什么” |
| `/diagnostic` | 算法诊断访谈 | 学习 | 与规划和执行分离，作为一级导航会放大实现阶段而非用户目标 |
| `/learning` | 规划、执行、六维证据、通知、来源候选 | 学习、证据、收件箱 | 一个长页面同时承担三个一级区域，状态与操作密度过高 |
| `/readiness` | 目标选择和准备度 | 目标与行动 | 与市场研究、实验是同一目标流程，却被拆成并列顶级页面 |
| `/market-research` | 真实来源和费用门禁 | 目标与行动 | 治理信息重要，但不应与用户目标并列为一级产品区域 |
| `/experiments` | 就业实验、真人评审、外部动作和收入 | 目标与行动 | 单页包含多种门禁、记录和敏感金额，缺少清晰的子导航 |

权限提示和移动行为不一致。

### 3.2 已存在但位置不合适的能力

- `learning-dashboard.tsx` 已有“站内通知”和“来源变化候选”，但它们被放在学习侧栏，
  不能覆盖实验门禁、证据到期、备份或外部服务状态；
- `learning-execution-panel.tsx` 已有六维证据和“不是掌握百分比”的正确边界，但只有进入
  某次学习执行后才能看到，缺少跨记录的独立证据中心；
- `learning-dashboard.tsx` 已有“今天从可信记录开始”和“生成今日任务”，但默认首页仍
  是产品介绍，没有聚合到期复习、阻断和最近变化；
- `system-settings.tsx` 同时承载站内通知、邮件和 AI 供应商，配置与需要处理的事项混在
  同一页；
- 当前目标、精确技能包版本和阻断状态分散在各组件内部，没有稳定的页面上下文区域。

## 5. 关键流程基线

现有端到端流程是：

```text
诊断 → 规划预览 → 保存规划 → 创建学习执行锁 → 今日任务 → 六维证据
     → 选择目标 → 准备度 → 就业实验草稿 → 市场研究边界
```

业务边界已经被测试覆盖，但用户必须在多个并列页面间自行理解关系。目标流程应改写为：

```text
今日发现下一步
  → 在学习中执行任务
  → 在证据中查看本次产生了什么、仍缺什么
  → 在收件箱处理复测、来源变化或门禁
  → 仅在用户选定目标后进入目标与行动
```

这只是信息组织变化，不改变任何后端状态机或证据等级。

## 7. 可比较方向稿

三个方向都遵守已确认一级信息架构，并保留“完成不等于掌握”。差异主要在信息密度、视觉
重心和长时间使用方式，不包含 Logo 或公开品牌资产。

### 7.1 方向 A：证据工作台（推荐）

定位：克制、清晰、长期使用友好；延续“静水深流”的低刺激色彩，但从营销式大标题转向
任务与证据优先。吸收 GOV.UK 的明确表达、Carbon 的状态层级和 Primer 的产品导航方法，
不复制其组件或品牌。

```text
┌──────────────┬─────────────────────────────────────────────────────────┐
│ 云奕学       │ 今日                         algorithm@0.2.2 · 有 2 项阻断 │
│              ├─────────────────────────────────────────────────────────┤
│ ● 今日       │ 当前任务                    │ 到期复习                    │
│   学习       │ 双语言数组遍历 · 35 分钟     │ 第 7 天主动提取 · 今天       │
│   证据       │ 为什么做 / 完成标准 / 开始   │ 保持证据：尚未产生            │
│   目标与行动 ├─────────────────────────────┴───────────────────────────┤
│   收件箱  3  │ 阻断事项                    最近变化                     │
│              │ 操作证据未 verified          来源候选待复核               │
│   设置       │ 仅影响就业实验，不影响学习    影响范围 / 时间 / 下一步       │
└──────────────┴─────────────────────────────────────────────────────────┘
```

移动端按“当前任务 → 完成标准 → 到期复习 → 阻断 → 最近变化”排序，底部固定“今日、学习、
证据、收件箱、更多”。状态同时显示文字，不依赖颜色。

优点：最符合六个持续问题；信息足够但不拥挤；能复用现有色彩和原生 CSS；迁移风险最低。
风险：需要严格限制“今日”卡片数量，否则会退化成另一个长仪表盘。

### 7.2 方向 B：专注画布

定位：一次只突出一个学习任务，其他信息通过紧凑上下文栏和分段页面进入。

```text
┌──────────┬─────────────────────────────────────────────────────────────┐
│ 导航     │ 今日 / 当前任务              35 分钟 · 无外发 · 本机 Runner │
│          ├─────────────────────────────────────────────────────────────┤
│          │ 双语言数组遍历                                             │
│          │ 为什么做                                                   │
│          │ 完成标准                                                   │
│          │ [开始任务]                                                 │
│          ├─────────────────────────────────────────────────────────────┤
│          │ 下一步：第 7 天复习     阻断：操作证据尚未 verified          │
└──────────┴─────────────────────────────────────────────────────────────┘
```

优点：认知负担最低，适合连续学习；移动阅读顺序自然。
风险：证据、来源和变化被放到下一层后，可能降低用户对限制的感知；不适合作为收件箱和复杂
实验的唯一布局。

### 7.3 方向 C：状态控制台

定位：以紧凑列表、筛选和时间线展示大量证据、来源、门禁和审计状态。

```text
┌──────────────┬─────────────────────────────────────────────────────────┐
│ 导航         │ 今日  任务 2  复习 1  阻断 2  变化 4                    │
│              ├─────────────────────────────────────────────────────────┤
│              │ 类型    范围                 状态       下一步           │
│              │ 任务    数组遍历             可开始     35 分钟          │
│              │ 复习    保持证据             到期       今天完成         │
│              │ 门禁    employment/cpp       阻塞       补验证证据       │
│              │ 来源    algorithm@0.2.2      待复核     查看差异         │
└──────────────┴─────────────────────────────────────────────────────────┘
```

优点：跨来源、证据和实验的状态对比效率最高；适合收件箱和系统状态。
风险：对每天两小时学习过于像运维控制台，阅读疲劳和“状态即进度”的误解风险最高；移动端
需要大量重排。

### 7.4 比较与推荐

| 维度 | A 证据工作台 | B 专注画布 | C 状态控制台 |
| --- | --- | --- | --- |
| 当前任务可见性 | 高 | 最高 | 中 |
| 完成标准与原因 | 高 | 最高 | 中 |
| 证据限制可见性 | 最高 | 中 | 高 |
| 阻断和变化处理 | 高 | 中 | 最高 |
