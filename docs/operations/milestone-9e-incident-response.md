# 第九里程碑 9E：支持、安全与运营手册

> 状态：仅供本地合成候选演练。本文不构成 24/7 服务承诺、安全认证、隐私合规认证或真实用户
> 放行。专用支持/隐私邮箱、真实 Clerk、真实用户、云端修改和付费资源均未启用。

## 1. 值守与分流

唯一负责人为 `owner_operator`。支持时间为中国时间工作日 10:00–18:00；普通产品支持、账号
恢复、内容纠错和滥用申诉在 2 个工作日内首次响应，隐私请求与安全报告在 1 个工作日内首次
响应。非工作时间不承诺即时响应，也不宣传 SLA 或确定修复时间。

产品支持、账号恢复、安全漏洞、隐私请求、内容纠错与滥用申诉必须分别建单。允许字段只有
类别、160 字以内摘要和 4,000 字以内必要说明。附件始终关闭；不得要求身份证、合同、账单、
银行材料、完整日志、数据库、凭据或 token。9G 前必须另行建立专用支持/隐私联系渠道；公开
GitHub Issue 不能处理账号恢复、删除或未公开漏洞。

## 2. 支持访问

`support_restricted` 默认不能访问任何用户正文、普通 API、导出或数据库。普通临时访问流程为：

1. 支持人员持用户主动提供的精确工单 ID，选择受管原因码、最小范围和不超过 60 分钟的期限；
2. 所有者复核工单、人员、范围、期限和用户可见原因后批准，形成第二次确认；
3. `ticket_metadata` 只返回类别、状态和时间；`case_content` 还要求用户事先启用
   `support_diagnostics` 分项选择；
4. 每次读取先核验支持身份、授权状态、精确工单、范围和到期时间，再写入哈希链追加审计；
5. 用户或所有者可以随时撤销，到期自动拒绝；支持人员不能冒充用户或进入普通用户路由。

紧急访问只能由所有者创建，必须绑定安全事件编号，只能读取 `ticket_metadata`，最长 30 分钟，
并产生用户可见的事后通知待办。紧急访问不能绕过正文同意、扩大范围或改数据库。

## 3. 急停与恢复顺序

控制面保留邀请、Runner、外部 AI、真实来源、邮件五个分项开关，以及 `normal`、`read_only`、
`stopped` 三种服务状态。外部 AI、来源和邮件在 9E 固定关闭，不能通过 API 打开。控制变更必须
由所有者提供受管原因码，并写入追加式审计。

发现跨用户泄漏、账号接管、删除失效、无法估价费用或 Runner 隔离失败时：

1. 立即切换 `stopped`，停止邀请，并撤销未使用邀请；
2. 撤销受影响账号全部会话；Runner 事件还须停止 Broker，并只清理带云奕学专用标签的资源；
3. 保存最少化证据，只保留内部主体哈希、动作、结果、原因码、状态码与时间；
4. 确定影响范围、恢复点和通知义务。不得把正文、代码、邮箱、私有 URL、token 或支持说明写入
   指标；
5. 修复后先在合成环境验证，再进入 `read_only`，最后由所有者明确恢复 `normal`；
6. 恢复旧备份时必须重放删除账本。RPO 仍为 24 小时、RTO 仍为 4 小时，9F 必须重新演练。

控制面、健康检查、当前会话状态和登出路径在只读/停服时保留，以便恢复；这不允许普通业务写入。

## 4. 配额、容量与费用

登录、Runner、导出、搜索、通知和未来 AI 均有每用户与全局窗口、并发和超时政策。达到任一
上限时返回确定性的 `quota_exceeded` 或 `concurrency_limit_exceeded`，不得排队产生未知费用，
不得切换供应商或自动扩容。未来 AI 配额为零。

多用户月度预期不超过 ¥300，硬上限 ¥500，累计 ¥250/¥400 告警。现有腾讯云按月折算 ¥30；
9E 未创建新订阅，新增持续费用为 ¥0。邮件、真实 AI 和真实来源预算均为 ¥0。价格变化、无法
估价或硬上限触发时停止新增付费调用和邀请；禁止自动充值、扩容和跨分类挪用预算。

## 5. 事件处置矩阵

| 事件 | 立即动作 | 恢复门禁 |
| --- | --- | --- |
| 严重漏洞 | 停止受影响能力；必要时全站停服；保留最少证据 | 严重问题先遏制，修复经合成反例与回滚验证 |
| 依赖/镜像漏洞 | 停用受影响入口，不在练习时拉镜像 | 锁定新版本/摘要，重跑供应链、Runner 与回滚门禁 |
| 密钥疑似泄漏 | 撤销会话和凭据引用，停止相关供应商 | 新密钥只进入批准的凭据存储，验证旧密钥失效且日志无原文 |
| 身份供应商故障/退出 | 停止邀请和登录，不回退到 owner 或其他供应商 | 验证导出、撤销、回调和失败关闭；替代供应商须重新授权 |
| 数据泄漏/删除失效 | 全站停服、撤销会话、冻结邀请 | 确认范围、修复隔离/账本、完成所需通知与恢复演练 |
| Runner 隔离失败 | Runner 分项急停并停止 Broker | 精确镜像、Socket、十项矩阵、零容器残留和回滚全部复验 |
| 备份失败 | 停止覆盖可用备份；超过 RPO 前切只读 | 加密备份、异库恢复、逐表摘要、外键、删除账本与 RTO 通过 |
| 容量耗尽 | 停止邀请和高成本能力；配额拒绝 | 资源余量和批次上限有证据；扩容须报价与单独授权 |
| 供应商退出 | 分项关闭，先导出可移植数据 | 合同、地区、价格、删除、退出和回滚重新确认，禁止静默切换 |

严重漏洞目标为发现后 4 个支持时段小时内遏制、验证后 1 个工作日内给出修复或继续停服决定；
高风险为 1 个工作日内遏制、3 个工作日内给出决定；中风险 10 个工作日内排期；低风险进入明确
记录的待办。这些是内部目标，不是对外 SLA。计划维护尽量提前 24 小时通过产品内状态通知；
邮件在 9E 关闭。

## 6. 安全检查结果与残余风险

- API 使用 `no-store`、严格 CSP、HSTS（私有预发布）、拒绝嵌入、最小权限策略；Web 生产 CSP
  只允许同源连接，但 Next.js 当前仍需要内联脚本/样式，是 9F 前需复核的残余风险；
- 状态变更在合成 OIDC/受控私有模式校验精确 Origin，CORS 只允许 loopback 开发源；合成身份头
  只允许本地模式，生产配置缺失时失败关闭；
- 支持文本由 React 作为文本渲染，不使用 `dangerouslySetInnerHTML`；输入受长度和枚举约束，数据库
  使用参数化 SQL；
- 外部 URL、来源与 Runner 继续受既有 SSRF、域名、镜像摘要、断网、只读根和无 Socket 挂载边界；
- 审计只保存主体哈希和载荷摘要，SQLite/PostgreSQL 均安装禁止更新/删除的数据库触发器；并发
  哈希链和配额在更高负载 PostgreSQL 候选上的压力与故障注入仍属于 9F；
- 自动化与桌面演练只能证明覆盖范围，不证明零风险，也不能替代安全、隐私或法律专业复核。

演练记录位于 `governance/operations/milestone-9e-drills.json`。9F 必须重新验证真实候选数据库、
身份回调、TLS、Origin、Cookie、缓存、告警、备份恢复和服务回滚。
