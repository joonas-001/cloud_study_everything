# SQLite 加密备份与恢复

## 1. 范围与目标

6A 提供一致性 SQLite 快照、分块认证加密、保留计划和恢复校验。目标为每日备份、
保留最近 7 个日备份及 4 个周备份，RPO 不超过 24 小时，恢复操作目标为 4 小时内完成。

本地备份与数据库位于同一主机时不能抵御主机或磁盘整体丢失。6B 必须为加密制品配置
异机副本，并在私有预发布验收前完成一次从异机副本恢复的演练。

## 2. 加密格式

- SQLite 使用只读源连接和 SQLite Backup API 生成一致性快照；
- 快照先执行 `quick_check` 和外键检查，再记录 Alembic 版本、逐表行数、字节数和 SHA-256；
- 数据密钥使用 AES-256-GCM 分块加密，每块具有独立 nonce 和认证标签；
- 数据密钥使用至少 3072 位 RSA 公钥与 OAEP-SHA256 封装；
- 信封元数据参与每一块认证，载荷另有 SHA-256；
- 私钥不进入服务器、仓库、SQLite、日志或备份制品。

加密制品扩展名为 `.csbak`。`inspect` 只展示非秘密信封元数据，不能证明备份可恢复；
只有使用离线私钥完成恢复与数据库校验才构成恢复证据。

## 3. 离线生成密钥

仅项目所有者在受控离线位置执行：

```text
python tools/manage_backup.py keygen --private-key <离线路径> --public-key <临时公钥路径>
```

工具拒绝覆盖已有密钥。将公钥复制到运行主机后，删除不必要的中转副本；私钥至少保留两份
独立离线副本。当前格式的私钥 PEM 本身未加口令，因此离线介质必须具备磁盘加密和访问控制。

## 4. 创建与保留

手动创建：

```text
python tools/manage_backup.py create --database <SQLite路径> --output <新制品路径> --public-key <公钥路径>
```

定时任务使用 `scheduled` 创建严格命名的时间戳制品，并应用 7 日加 4 周保留。单独运行
`retention` 默认只显示将删除的文件；只有显式添加 `--apply` 才删除，而且只处理
`cloud-study-YYYYMMDDTHHMMSSZ.csbak` 格式的普通非符号链接文件。

每次备份成功后应复制加密制品到异机存储。上传机制和真实对象存储凭据属于 6B，不在
6A 中调用或创建。

## 5. 恢复演练

1. 从异机存储取得一个加密制品；
2. 在隔离目录指定一个不存在的恢复目标；
3. 使用离线私钥运行：

```text
python tools/manage_backup.py restore --backup <制品> --target-database <新SQLite路径> --private-key <离线私钥>
```

4. 核验工具返回的时间、策略版本、Alembic 版本、摘要和逐表行数；
5. 用恢复数据库启动隔离实例，抽查诊断、规划、学习、来源、证据、市场研究和实验历史；
6. 停止隔离实例，记录开始与结束时间、制品摘要、结果和操作者；
7. 擦除演练中不再需要的私钥工作副本，保留原加密备份与无敏感内容的报告。

恢复工具拒绝覆盖已有目标；认证失败、截断、额外数据、摘要不符、外键错误、版本或行数不符
都会失败，并且不会留下目标数据库。

## 6. 恢复失败

不要修改原备份或原数据库。依次检查制品完整性、是否使用对应私钥、磁盘空间和文件权限。
若一个制品失败，保留失败证据后尝试上一份已验证备份。所有候选都失败时停止上线并回到
本地只读版本，不创建空数据库冒充恢复成功。
