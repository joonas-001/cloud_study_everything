# 第六里程碑 6A 合成备份恢复演练记录

> 日期：2026-08-09（Asia/Shanghai）
> 范围：本地合成 SQLite 数据库；不包含真实用户数据、云资源、异机副本或 6B 操作。

## 1. 目的

验证仓库提供的迁移、加密备份、源库丢失后恢复、完整性校验和私有预发布预检能够形成
一条可重复的本地证据链。本记录不能代替 6B 私有预发布中的异机副本恢复演练，也不能
证明 RPO 24 小时或 RTO 4 小时已经在真实主机上达成。

## 2. 演练环境

- Node.js：24.14.0；
- Python：3.14.3；
- pnpm：11.16.0；
- uv：0.11.32；
- 数据库：由 Alembic 从空文件迁移至 `0010` 的合成 SQLite 数据库；
- 加密协议：`RSA-OAEP-SHA256+AES-256-GCM`，RSA 公钥 3072 位；
- 部署策略：`single-user-singapore@1.0.0`。

所有数据库、备份制品和临时密钥均位于被 Git 忽略的仓库本地临时目录，未提交到仓库。
离线私钥只用于本次合成演练，不是任何真实环境凭据。

## 3. 执行与结果

1. 使用仓库迁移入口创建合成数据库，Alembic 依次升级至 `0010`。
2. 使用 `tools/manage_backup.py keygen` 生成本次演练密钥对。
3. 使用 `tools/manage_backup.py create` 创建加密备份，再通过 `inspect` 读取非秘密信封元数据。
4. 验证备份制品存在后删除合成源数据库，模拟源库丢失。
5. 使用离线私钥将备份恢复到一个此前不存在的新路径。
6. 对恢复库执行摘要、Schema、SQLite 快速检查、外键和基础行数复核。
7. 使用恢复库和合成配置执行 `tools/deployment_preflight.py`。

结果如下：

| 检查 | 结果 |
| --- | --- |
| 备份格式版本 | `1` |
| 数据库大小 | `700416` 字节 |
| 清单与恢复库 SHA-256 | `83861196986e832d8ba756cd5eaa6de013bd9ab93382e0b7c4222e5e6d4f2683`，一致 |
| Alembic 版本 | `0010` |
| SQLite `quick_check` | `ok` |
| 外键违规 | `0` |
| 默认设置行 | `app_settings=1`、`notification_preferences=1` |
| 私有预发布模式 | `private_preview` |
| 远程 Runner | `false` |
| 外部调用 | `false` |
| 目标区域 | `singapore` |
| 预检退出码 | `0` |

首次在 Windows 实跑预检时发现 `subprocess` 不能通过无扩展名的 `pnpm` 调用
`pnpm.cmd`。后续修复按平台选择 `pnpm.cmd` 或 `pnpm`；针对部署与备份的自动化测试
通过 8 项，另有 1 项仅因 Windows 不提供 POSIX 文件模式而按既有条件跳过，修复后的
真实预检退出码为 0。

## 4. 结论与剩余边界

本次本地合成演练通过，证明 6A 仓库工具能够在源库被删除后从认证加密制品恢复一个
摘要、Schema、外键和受管默认记录均一致的新数据库，并能通过私有预发布预检。

仍未验证的内容属于后续阶段：

- 腾讯云主机和 Tailscale 实际身份头；
- 异机备份复制及从异机副本恢复；
- 真实数据迁移、真实 RPO/RTO 和灾难恢复时长；
- 远程 Runner、真实 AI、真实来源访问、邮件或互联网公开上线。
