## 版本化启用边界

- 保留 `single-user-singapore-v1.json` 作为 6B／6C 的不可变关闭策略；
- 6D 使用 `single-user-singapore-v2.json`，版本 `1.1.0`，只把远程 Runner 改为启用；
- 6D 起新生成的每日加密备份必须显式记录策略版本 `1.1.0`；既有 `1.0.0` 备份保持可读，
  不改写历史制品；
- 外部 AI、真实来源和邮件继续为硬关闭；预算、单用户身份、Tailnet-only、SQLite、备份和
  日志规则不变；
- Broker 由独立 `cloud-study-runner` 身份运行，只有该身份属于 Docker 组；FastAPI 身份
  继续不能访问 Docker Socket；
- `tools/activate_controlled_live_ubuntu.sh` 只有在精确 app／Runner 提交标记、锁定镜像、
  Docker 版本、策略、服务单元、环境权限和零容器残留全部匹配时才允许启用；
- 激活脚本在 API 接入前重新执行十项矩阵，任一失败自动停止并禁用 Broker、恢复原环境文件
  并尝试恢复 API，不得带病继续。

## 正式执行顺序

1. 确认精确应用提交和 Runner 提交，记录 40 位 Git 哈希及 `git archive` SHA-256；
2. 本地完整 `release-readiness` 和对应 GitHub Actions 全部成功；
3. 冻结本地写入，创建最终加密备份，并记录本地数据库 SHA-256、Alembic 版本和无正文语义
   摘要；
4. 在云端创建不会覆盖当前版本的新 release，验证归档摘要后安装锁定依赖和生产构建；
5. 停止 live API／Web，备份合成云数据库和现有环境文件；
6. 恢复真实数据库到新路径，执行 Alembic 正式历史并复核 47 张表、逐表行数、外键、事件
   顺序、内容锁和语义摘要；任何差异都停止；
7. 原子切换精确 release，安装匹配的 systemd 单元和提交标记；
8. 执行部署预检、TLS、唯一身份、错误身份、退出／撤销、API、桌面和移动关键路径烟雾；
9. 执行 `activate_controlled_live_ubuntu.sh --apply`；脚本先重跑 Runner 十项矩阵，成功后才
   重启 live API 并持久启用 Broker；
10. 复核公网端口仍关闭、API/Web 只监听回环、Tailscale Serve 只对所有者开放、项目容器
    残留为零、备份计时器正常、磁盘／内存／Swap 和费用告警正常；
11. 进入观察期，本地数据库和旧云端 release 保持只读可回退；任一停止条件触发时立即关闭
    Runner、恢复原环境和数据库、切回旧 release。

## 必须保留的无敏感证据

- 授权时间、操作者、精确提交、归档摘要和策略版本；
- 最终加密备份名称与摘要，不记录私钥或正文；
- 数据库 Schema、逐表行数／语义摘要、外键、事件顺序和内容锁对比；
- TLS、身份、授权、会话撤销、桌面／移动烟雾结果；
- Runner 十项矩阵、镜像摘要、Socket 权限、Docker 权限分离和容器清理；
- 服务启用状态、监听端口、资源余量、备份计时器、费用告警和回滚验证；
- 观察期开始／结束、期间错误、安全事件、费用和最终是否接受上线。
