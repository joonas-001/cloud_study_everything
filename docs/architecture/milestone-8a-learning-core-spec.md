## 2. 能力图边界

机器规格固定 12 个域、46 个能力范围、34 个学习单元，受内容预算约束最多 48 个能力和
36 个单元。能力 ID、逐项前置依赖、诊断信号和补救单元以 JSON 规格为唯一 8A 机器真值。

| 域 | 能力范围 | 主要前置 | 本共同主干不包含 |
| --- | --- | --- | --- |
| P 双语言编程 | 控制流、函数/I/O、C++/STL、Python 容器与运行特征 | 无；诊断后按需补救 | 高级元编程、框架开发、完整语言教程 |
| M 必要数学 | 逻辑/集合、函数/关系、归纳/求和/对数、组合/概率 | 无；只按算法需要补 | 完整离散数学、高等概率、无关微积分深化 |
| A 分析与正确性 | 渐近分析、情形假设、递推式、不变量/归纳/反例 | P、M 的相应能力 | 高级摊还、随机算法严格分析、复杂性理论深化 |
| L 线性结构 | 数组、链表、栈/队列/双端队列、结构选择 | P、A | 并发容器、持久化结构、框架专属容器 |
| H 哈希与集合 | map/set 语义、冲突/负载、应用边界 | L、A | 密码学哈希、分布式哈希、数据库索引工程 |

| R 递归与分治 | 状态/基例、分治/递推、栈风险/迭代转换 | P、M、A、L | 主定理全部边界证明、编译器级递归消除 |

能力图必须是有向无环图。通用引擎只理解稳定 ID、前置边和策略，不得包含 `p-*`、`g-*`

## 3. 诊断协议

### 3.1 题库与会话预算

- 受管题库 64–84 题；阻断度高的 P、M、A 入口能力至少准备两个独立信号；
- 单次最多 36 题或 50 分钟，先到者停止；未覆盖能力明确标记 `inconclusive`；
- 自述和自由文本结构有效只能帮助选题，不能作为确定性正向信号；
- 跳过和“不确定”不等于错误，也不进入负向计数；
- 题目、答案、难度、范围、来源、歧义审查和响应效果均随精确技能包版本锁定。

### 3.2 三种能力状态

| 状态 | 确定性条件 | 对规划的影响 |
| --- | --- | --- |
| `ready` | 至少两个相互独立的确定性正向信号，且前置能力没有 `remediation_required` | 可跳过重复讲解，但保留阶段检查和延迟复测 |
| `remediation_required` | 出现受管关键错误，或至少两个独立负向信号 | 先安排绑定的补救单元；不得静默解锁下游 |
| `inconclusive` | 信号不足、仅自述/自由文本、跳过/不确定或达到会话上限 | 安排低风险入门或补充检查，并明确无法判断 |

选题顺序固定为“下游阻断度 → 区分补救与继续的能力 → 减少重复 → 稳定题目 ID”。任何
损坏状态、无法解释的并列或规则异常都回退受管固定序列并记录原因。诊断只产生路径信号，
不能产生 `supported`、`verified`、`retained` 或整体掌握。

## 4. 单元、活动和证据覆盖

34 个单元的计划内容时间为 4,740 分钟，不含诊断、可选补救、阶段检查和延迟复测。按每日
约 120 分钟约需 40 个纯内容日；实际日历还要包含延期、纠错和第 1、2、4、7、15 天复测，
不能承诺固定完成日期。

| 域 | 单元数 | 计划分钟 | 必需活动 | Runner 边界 |
| --- | ---: | ---: | --- | --- |
| P | 3 | 420 | 学习、主动提取、确定性题、纠错、双语言迁移、复测 | C++ 与 Python 都要独立通过 |
| M | 3 | 450 | 学习、主动提取、确定性题、证明/推导、反例、复测 | 数学本身不强制 Runner；嵌入算法任务时再运行 |
| A | 3 | 450 | 分析、推导、反例、实验代码、迁移、复测 | 只验证可执行测量与代表操作，不自动判定完整证明 |
| L | 3 | 420 | 结构选择、实现、纠错、迁移、复测 | 两种语言分别验证代表操作和边界 |
| H | 2 | 270 | 语义、复杂度条件、实现、冲突纠错、复测 | 测试重复键、负载假设和边界输入 |
| S | 3 | 420 | 跟踪、实现、稳定性反例、选择、复测 | 固定隐藏测试覆盖边界和复杂度可观察代理 |
| R | 2 | 270 | 状态跟踪、递推、实现、栈风险纠错、复测 | 递归与迭代版本分别测试 |
| T | 3 | 390 | 表示、遍历、不变量、实现、迁移、复测 | 遍历、BST、堆按精确操作范围验证 |
| G | 4 | 540 | 建模、遍历、适用条件、反例、实现、复测 | 图表示、断连、环、权重条件进入测试 |
| Y | 2 | 270 | 选择、交换论证、反例、实现、迁移、复测 | Runner 只证明测试范围内行为，不证明贪心正确性 |
| D | 3 | 420 | 状态设计、实现、优化、反例、迁移、复测 | 两种语言独立测试状态、边界和空间优化 |
| Q | 3 | 420 | 建模、测试、调试、性能、作品、迁移、复测 | Runner 验证代码范围；作品正确性仍需真人量表 |

每个域必须包含 `study`、`active_recall`、`structured_check`、`correction`、`transfer` 和
`review`。只有确定性结构检查或预置错误纠错最多产生 `supported`；锁定 Runner 且完整测试
通过最多产生精确操作范围的 `verified`；同范围延迟复测通过才可产生 `retained`。解释、证明
和作品文本结构有效只允许推进，未经独立真人评审不得声称正确。

## 5. C++ 与 Python 差异清单

8B 内容必须显式覆盖：

- 静态类型与动态类型、整数范围与 Python 任意精度整数；
- 值语义、引用/指针、对象生命周期和复制成本；
- `vector/string/map/unordered_map/set/priority_queue` 与 Python `list/dict/set/heapq/deque`；
- 迭代器失效、下标边界、负索引、切片和容器修改语义；
- 排序接口、稳定性保证、比较器/键函数及其约束；
- 递归深度、调用开销、输入输出性能和内存布局；
- C++ 编译错误/未定义行为与 Python 运行时异常；
- 同一算法的渐近复杂度相同不代表常数、内存和安全边界相同。

关键操作不能用“另一种语言已通过”替代。继续使用 Runner `1.1.0`、GCC 15.2.0 和 Python
3.14.3 的精确镜像摘要；若 8B 证明必须改变协议、运行时或镜像，立即停止并另行确认。

## 6. 每日拆分与动态重排

- 默认目标和硬上限均为 120 分钟；活动为 10–60 分钟，长单元必须拆分；
- 优先顺序为到期保持、失败纠错、阻断前置、新内容；
- 一天最多引入一个高认知负荷新域；
- 未完成、逾期或用户暂停只触发追加式重排，不记为能力失败；
- 只有用户当日明确选择并留下原因时才可超过默认上限，系统不得形成长期超时默认值；
- 重排不能跨精确技能版本复制证据，也不能改变已锁定复习策略。

## 7. 四分支门禁

8D 只实现门禁和准确入口，不制作四分支课程。机器规格为工程、面试、竞赛和理论分别列出
能力范围；共同规则是：

1. 显示满足、过期、缺失和待复核范围，不显示总掌握百分比；
2. Runner 基础设施探针、学习执行 `completed`、自评或 AI 评价都不能解锁；
3. 工程、面试和竞赛要求代表性操作 `verified` 与部分 `retained`；
4. 理论分支的证明与反例要求按当前受管量表进行独立真人评审；
5. 每个入口都必须显示“不表示完整工程能力／通过面试／竞赛等级／完整理论训练”；
6. 用户没有选择目标时不默认选择分支。

## 9. `algorithm@0.3.0` 契约差异草案

8B 应先发布通用契约，再创建技能包草稿。8A 只批准以下差异方向：

| 契约 | 需要增加的通用字段或文件 | 兼容策略 |
| --- | --- | --- |
| manifest | `capability_graph`、`diagnostic_policy`、`content_coverage`、`branch_gate_policy` 内容种类 | manifest schema 建议升至 `1.1.0`；旧 `1.0.0` 适配器继续读取 |
| capability graph（新） | 稳定能力 ID、域、前置边、不包含范围、诊断信号、补救单元 | 不能把算法 ID 写入引擎枚举；必须检查引用和 DAG |
| diagnostic definition | 题目版本、能力范围、难度、信号、响应效果、选题原因码、提前停止资格、来源和歧义状态 | 建议 v2；旧固定序列定义继续由 v1 适配器执行 |
| learning definition | 单元/活动能力范围、主动提取/证明元数据、语言、每日拆分、完成和证据上限 | 新字段只作用于 0.3.0；旧活动语义不变 |
| assessment/rubric | 精确能力范围、语言、测试集合、独立评审要求和时效 | 不允许把旧证据升级到新范围 |
| branch gate（新） | 分支、所需能力、证据条件、时效、阻断标记和限制文案 | 只计算入口状态，不创建分支课程 |
| profile/export（8E） | 精确版本、范围、证据、时效、验证方式、待办、能/不能证明的内容 | 默认本地，不含敏感正文或公开链接 |
| shadow review（8E） | 模型/参数/输入版本、样本、预测、固定策略结果和 `insufficient_data` | 与权威任务和证据存储隔离 |

候选引擎契约范围建议为 `>=0.4.0 <0.5.0`；Runner 协议保持 `1.1.0`。该建议需在 8B 以
兼容矩阵验证，不能在 8A 修改现有契约或注册表。

历史策略固定为：0.1.0–0.2.2 字节和摘要不变；旧记录继续读取和执行原锁；0.3.0 重新诊断；
证据、诊断和规划不迁移；0.3.0 第一次被持久化引用后立即锁定。未来数据库迁移只能新增可空
引用或独立表，回滚后必须完整保留旧记录，8G 做真实副本演练。
