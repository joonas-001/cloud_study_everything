## 授权边界

项目所有者于 2026-09-09 明确“授权9E”。本阶段只使用合成身份、合成工单和本地候选数据库，
不创建 Clerk、邮箱、云资源或付费资源，不修改 6D 服务器，不接真实身份、真实用户或个人数据，
不调用外部 AI/来源，不发送邮件，不开放注册或公开发布。9E 控制只在合成多用户模式生效，当前
6D/本地所有者单用户运行仍由原有部署门禁控制。

## 实现

- Alembic `0015` 新增一张用户私有 `support_cases` 表和五张运营控制表；PostgreSQL 为支持工单
  增加强制 RLS，SQLite/PostgreSQL 为运营审计安装禁止更新和删除的触发器；
- 六类支持请求有固定负责人、字段、时段、首次响应目标和附件禁令；普通支持访问要求受限支持
  账号申请与所有者批准，正文范围还要求用户开启 `support_diagnostics`；
- 紧急访问固定为工单元数据、最长 30 分钟、必须绑定事件编号并显示事后通知待办；每次读取均
  核验精确支持账号、工单、范围、状态与期限；
- 邀请、Runner、外部 AI、来源和邮件分别急停，全站支持只读和停服；现有账号暂停、邀请撤销、
  会话全撤销继续复用，9E 增加批量撤销入口；
- 登录、Runner、导出、搜索、通知和未来 AI 定义每用户/全局窗口、并发和超时；未来 AI 配额为
  零，外部 AI、来源和邮件在 9E 不能被 API 打开；
- 指标只保存 SHA-256 内部主体标识、动作、结果、原因码、状态码和时间，并滚动保留 7 天；支持
  正文、学习正文、代码、邮箱、URL、凭据和 token 不进入指标；
- 设置页增加合成候选状态、支持承诺、预算边界、最少化工单、授权可见性和所有者急停入口。
