# 诊断访谈最小闭环架构

> 状态：已确认实施
> 确认日期：2026-07-27
> 适用范围：算法技能包草稿诊断预览、本地确定性测试供应商、外部 AI 授权门禁
> 不包含：真实 AI API、正式学习计划、掌握结论、代码执行和变现建议

## 1. 目标

本里程碑验证以下最小闭环：

1. 用户创建或恢复一个诊断会话；
2. 系统展示问题及提问原因；
3. 用户可以回答、跳过、标记不确定或更正历史回答；
4. 系统根据当前有效回答重新计算后续问题；
5. 会话锁定供应商、模型、凭据引用和技能包精确版本；
6. 所有状态变化保留审计记录；
7. 用户可以结束会话，或由两小时无操作规则结束会话；
8. 页面明确展示草稿预览、外部发送状态和代码不执行边界。

## 2. 已确认决定

- 首版只使用本地确定性测试供应商，不调用真实外部 AI；
- 全局外部 AI 发送开关默认关闭；
- 创建外部 AI 对话时还必须进行第二层对话级确认；
- 首版使用普通非流式 HTTP；
- 每个技能包精确版本最多存在一个活动诊断会话；
- 用户粘贴的代码只作为不可信文本保存和审查，绝不执行；
- 首个访谈页面应用“静水深流”视觉提案；
- `draft` 技能包只能进入受限的本地诊断预览；
- 草稿预览不得生成正式计划、掌握结论或变现建议。

## 3. 草稿预览边界

当技能包状态为 `draft` 时，创建诊断会话必须同时满足：

- 请求显式声明 `preview: true`；
- 使用 `local-deterministic` 供应商；
- 使用该供应商声明的固定测试模型；
- `credential_reference` 为空；
- `external_ai_consent` 为 `false`；
- 技能包 `availability` 为 `available`；
- 页面持续显示“草稿预览”；
- 保存的数据标记为预览数据。

预览不会改变技能包生命周期状态。技能包仍需经过来源、内容、评估、兼容性和人工授权门禁才能进入 `active`。

## 4. 两层外部 AI 授权

### 4.1 全局门禁

`app_settings.external_ai_enabled` 表示后端是否有权调用外部 AI。默认值为 `false`。

关闭时：

- 后端拒绝所有外部 AI 请求；
- 已保存的凭据引用可以保留，但不得读取或调用；
- 本地确定性功能继续可用；
- 界面明确说明哪些功能受限。

### 4.2 对话级确认

即使全局门禁开启，创建外部 AI 对话仍必须记录：

- 用户明确确认；
- 供应商和模型；
- 凭据引用；
- 将发送的数据类别；
- 确认时间。

当前里程碑没有外部供应商适配器，因此不会产生任何外部请求。测试会使用模拟能力声明验证两层门禁。

## 5. 会话状态

```text
active
├── 用户结束 ───────────────> ended
├── 连续无操作达到时限 ─────> ended
├── 确认的致命异常 ─────────> failed
└── 正式计划校验并保存 ─────> plan_saved（本里程碑不可达）
```

`ended`、`failed` 和 `plan_saved` 都是终态。终态会话只能读取，不能追加回答或更改供应商、模型和技能包版本。

本里程碑没有后台定时任务。读取或修改会话时，服务根据最后活动时间确定是否已经超时，并以原子事务写入结束状态和审计事件。

## 6. 数据模型

### 6.1 `app_settings`

- 单例主键；
- 是否允许外部 AI；
- 会话无操作超时分钟数，默认 120；
- 最近更新时间。

### 6.2 `diagnostic_sessions`

- UUID；
- 技能包 ID 和精确版本；
- 是否为草稿预览；
- 锁定的供应商、模型和凭据引用；
- 对话级外部 AI 确认；
- 状态、当前问题、创建时间、最后活动时间和结束原因。

SQLite 使用部分唯一索引保证同一 `(skill_id, skill_version)` 最多存在一个 `active` 会话。

### 6.3 `diagnostic_answers`

回答采用追加修订：

- 问题 ID；
- `answered`、`skipped` 或 `uncertain`；
- 可选文本内容；
- 修订号；
- 被更正回答的 ID；
- 创建时间。

旧修订不会被覆盖。系统只把每个问题的最新修订用于当前诊断路径。

### 6.4 `diagnostic_events`

记录：

- 会话创建与恢复；
- 回答、跳过、不确定和更正；
- 路径重新计算；
- 全局外发设置变化；
- 用户结束、无操作结束和失败。

事件负载只保存完成审计所需的结构化元数据，不复制 API 密钥。

## 7. 技能包诊断定义

诊断问题属于技能包版本化内容，不硬编码进通用学习引擎。

技能包 manifest 中的内容条目必须声明 `kind`。诊断定义使用 `diagnostic_definition`，并通过 `contracts/skill-pack/diagnostic-definition.schema.json` 校验。

每个问题至少包含：

- 稳定问题 ID；
- 问题文本；
- 提问原因；
- 回答类型；
- 针对 `answered`、`skipped` 和 `uncertain` 的下一问题。

确定性测试供应商只根据结构化回答状态选择下一问题，不声称理解或评价用户自由文本的正确性。

## 8. API

首版 API：

- `GET /settings/privacy`
- `PUT /settings/privacy`
- `POST /diagnostic-sessions`
- `GET /diagnostic-sessions/active`
- `GET /diagnostic-sessions/{session_id}`
- `POST /diagnostic-sessions/{session_id}/answers`
- `POST /diagnostic-sessions/{session_id}/answers/{question_id}/corrections`
- `POST /diagnostic-sessions/{session_id}/end`

重复创建活动会话返回冲突响应，并提供现有会话 ID。终态会话写操作返回冲突响应。

## 9. 前端

访谈页面必须包含：

- 草稿预览和不执行代码提示；
- 当前供应商、模型、技能包版本和外部发送状态；
- 当前问题及提问原因；
- 回答、跳过、不确定、更正和结束操作；
- 活动会话恢复；
- 空、加载、错误和完成待结束状态；
- 键盘焦点、文本标签、`aria-live` 状态和减少动效支持；
- 桌面与移动布局。

## 10. 验证

至少包括：

- 数据库迁移与唯一活动会话约束；
- 外部 AI 两层门禁；
- 草稿预览限制；
- 供应商、模型和技能包版本不可变；
- 回答修订与路径重算；
- 两小时无操作结束；
- API 集成测试；
- 前端状态与生产构建；
- 浏览器端关键流程、移动视口和基本无障碍检查；
- OpenAPI 与生成类型无漂移；
- 完整 `release-readiness`。
