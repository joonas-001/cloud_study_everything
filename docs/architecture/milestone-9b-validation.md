## 1. 结论

9B 已在授权范围内完成用户主体、对象归属、应用层隔离、PostgreSQL 行级安全和
SQLite→PostgreSQL 合成迁移基础。验证只使用本地预置合成身份和合成数据；没有接入 Clerk、
创建真实账号、处理真实个人数据、修改 6D 生产 SQLite 或服务器，也没有启用真实 AI、来源、
邮件、公开注册或新增付费资源。

本阶段的通过只证明 9B 数据与隔离基础具备进入 9C 决策/实施门禁的条件，不授权 9C–9H，
也不表示可以邀请真实用户。

## 2. 实现边界

- 使用不可从邮箱推导的稳定内部 `user_id`，外部身份按 `(issuer, subject)` 唯一映射；
- 固定角色为 `user`、`owner_operator`、`support_restricted`，账号状态为 `active`、
  `suspended`、`deletion_pending`、`deleted`，状态变化使用追加事件记录；
- HTTP 合成适配器只在本地验证模式启用，不接受客户端提供内部 `user_id`；
- 原有 47 张模型表明确分类为 39 张用户私有表和 8 张全局受管表；9B 新增每用户
  `user_settings` 后共有 40 张用户私有表，并新增 4 张身份控制面表，总计 52 张模型表；
- `app_settings` 保留为全局单例策略，`user_settings` 保存每用户 AI 选择和会话超时；外部 AI
  只有在全局开关和当前用户开关同时开启时才可能进入既有后续门禁；
- ORM 查询、更新和删除自动按当前主体过滤；写入自动补齐所有者，并拒绝跨主体所有权和
  跨主体外键；`support_restricted` 默认不能读取用户数据；
- PostgreSQL 对 40 张私有表启用 RLS，应用事务使用本地事务变量设置当前主体；
- 旧单用户记录确定性归属到一个不透明 legacy owner，保留原业务 ID、时间和事件顺序；
- 含第二个主体时拒绝降级到 `0011`，必须恢复 9B 前备份，避免把多用户历史有损折叠。

## 4. PostgreSQL 实机证据

验证使用 Docker Desktop 中仅绑定 loopback 的临时容器：

`postgres:17.6-bookworm@sha256:f3bd19c606e442c3d7bdfa8002e03fe260a1023351e0ea4598032022b68dd6e3`

| 项目 | 结果 |
| --- | --- |
| 空库迁移 | PostgreSQL `0001→0012` 成功 |
| SQLite 复制 | 52 张模型表、22 行合成数据；源库前后摘要不变，目标逐表摘要一致 |
| RLS | 40 条策略；A/B 各只看到自己的诊断，B 猜测 A 通知不可见 |
| 跨主体写入 | 更新 0 行、删除 0 行；未设置主体时读取 0 行、写入被 RLS 拒绝 |
| 应用角色 | 非超级用户，无建库、建角色权限 |
| 复制后序列 | 新建用户的 `user_settings.id=4`、`notification_preferences.id=4` |
| 逻辑备份 | 244,537 字节；SHA-256 `36c086efdc322b7d02a1d55f3a8de21344fa16c9587ee46a70906cd3f1aeaab7` |
| 异库恢复 | 52 张模型表、28 行；恢复前后逐表摘要完全一致 |
| 往返 | 独立 owner-only 库 `0012→0011→0012` 成功，最终 53 张物理表（含 `alembic_version`）和 40 条 RLS |
| 有损降级 | 含 legacy owner 与 A/B/C 共 4 个主体时拒绝，版本保持 `0012` |

实测期间发现并修复两项只在严格 PostgreSQL 外键/序列语义下暴露的问题：主体及其状态事件
同批 flush 的插入顺序，以及复制后 `user_settings` 序列未推进。修复后重新执行静态检查、
9B 测试和完整 PostgreSQL 验证，结果均通过。

## 5. 回退与未授权事项

- SQLite 源库在复制期间只读，目标复制失败时使用同一 PostgreSQL 事务回滚；
- 单主体候选可往返到 `0011`；多主体候选禁止有损降级，回退方式是恢复 9B 前加密备份；
- 本次临时 PostgreSQL 数据库和容器在验证结束后删除，锁定镜像可留作可复现实验缓存；
- Clerk 套餐、数据位置、MFA、导出、退出与真实 OIDC/OAuth 仍留到 9C/9F 验证；
- 真实身份、邀请、邮件、隐私权利闭环、支持授权、容量/费用候选和真实用户内测均未实施。
