# 第三里程碑：来源、规划与学习面板

> 状态：已获项目所有者批准实施
> 确认日期：2026-07-27
> 适用范围：本地单用户验证、算法技能包草稿、确定性规划预览
> 不包含：真实 AI API、自动废弃技能包、后台常驻任务、正式掌握结论

## 1. 目标

第三里程碑建立以下最小闭环：

1. 技能包声明有限、可验证的权威来源目录；
2. 系统根据公开成果综合多位专家和权威机构的规划原则；
3. 已结束的诊断会话可以进入本地确定性规划预览；
4. 规划单元关联安排原因、完成标准和原始来源；
5. 用户每日首次开始学习时检查计划引用的受监测来源；
6. 来源变化只形成候选和影响报告，不自动修改技能包或计划；
7. 来源检查失败不阻止学习，但必须明确通知用户；
8. 站内通知是可靠记录，必要时可以在网站运行期间发送邮件；
9. AI 供应商配置采用独立档案和能力声明，对话创建后保持锁定。

## 2. 已确认边界

- 每个本地自然日最多自动检查一次，用户可以手动重新检查；
- 只检查技能包登记的来源，不声称覆盖所有权威平台；
- 优先使用官方 API、RSS、版本标识、`ETag` 和 `Last-Modified`；
- 遵守访问条款、robots 规则、速率限制和版权边界；
- 远程来源失败保留最近成功快照，学习面板继续可用；
- 无法检查不得记录为“没有更新”；
- 来源可访问但缺少可比较的 `ETag` 和 `Last-Modified` 时记录为
  `indeterminate`，提示人工复核，不下载正文冒充确定性比较；
- 来源变化不得自动触发 `deprecated`；
- 新版本、补充学习单元和计划变化必须由用户确认；
- 本阶段只实现本地确定性规划器和真实供应商接口；
- OpenAI、DeepSeek 和 Moonshot AI 不产生真实网络请求；
- 邮件不是站内通知的替代品，发送失败不得丢失站内记录；
- 网站关闭后不运行任务，重新启动后只处理仍然有效的待发邮件。

## 3. 规划预览限制

算法技能包 `0.1.0` 仍处于 `draft`。当前内容不足以生成覆盖整个算法技能和四条
分支的正式学习计划。

第三里程碑只允许创建：

- `is_preview: true` 的规划提案；
- 使用 `local-deterministic` 供应商和 `planner-sim-v1` 模型；
- 锁定算法技能包 `0.1.0`、来源目录版本和诊断会话；
- 明确标注无法判断自由文本回答是否正确；
- 不产生掌握结论、分支解锁或变现建议。

用户可以编辑、否决或保存规划预览。保存预览不激活技能包，也不代表正式计划已经通过。

## 4. 来源与专家证据

来源目录属于版本化技能包内容。每条来源至少记录：

- 稳定 ID、标题、作者或发布机构；
- 原始 URL；
- 来源类型和权威等级；
- 权威判断依据；
- 发布版本或发布日期；
- 检索日期；
- 检查方式；
- 版权与访问说明。

专家条目只表示对公开成果的结构化综合。系统不得：

- 冒充专家；
- 暗示专家参与或认可了计划；
- 使用无法验证的资历；
- 未经许可复制教材、论文或课程全文。

存在观点冲突时，必须记录冲突，不能静默选择。

## 5. 每日来源检查

```text
开始今日学习
├── 当天已检查 ─────────────> 返回已有结果
└── 当天未检查
    ├── 全部成功且无变化 ───> 记录成功
    ├── 任一来源不可访问 ───> 保留旧快照、创建警告通知
    └── 检测到元数据变化 ───> 创建待审查候选和通知
```

首个成功检查建立本地基线。之后的检查比较可用的 `ETag`、`Last-Modified`、最终 URL
和显式版本信息。元数据变化只是复核信号，不直接证明教学内容发生实质变化。

## 6. 通知与邮件

通知级别：

| 级别 | 示例 | 默认邮件行为 |
| --- | --- | --- |
| `required` | 验证码、安全或凭据事件 | 邮件通道启用时立即发送 |
| `action_required` | 更新候选、计划等待确认 | 按用户偏好延迟发送 |
| `warning` | 来源失败、数据可能过期 | 站内通知；按偏好升级邮件 |
| `info` | 无变化、恢复、普通状态 | 仅站内或摘要 |

邮件策略参考 GitLab、Discourse 和 Zulip 的分级、范围覆盖、延迟、已读取消、合并和频率限制
思路，但以本地单用户需求为准。

邮件凭据保存在 Windows 凭据管理器。SQLite 只保存凭据引用、发件配置、收件地址和投递状态。
邮件正文只包含必要摘要，详细学习数据留在本地网站。

## 7. AI 供应商配置

供应商档案包含：

- 供应商 ID 和显示名称；
- 独立适配器类型；
- 默认或自定义 Base URL；
- 凭据引用；
- 模型目录接口；
- 流式、工具和结构化输出等能力声明；
- 是否允许真实调用。

当前只有本地确定性供应商允许执行。真实供应商配置不得宣称连接成功，也不得被规划预览选择。

配置切换只影响新对话。已经创建的诊断或规划会话继续使用锁定的供应商、模型和凭据引用。

## 8. 验证

至少覆盖：

- 来源目录 Schema、内容摘要和引用完整性；
- 每日检查去重；
- 首次检查建立基线；
- 来源失败不阻断学习且产生通知；
- 失败不得伪装成无变化；
- 来源变化只产生候选；
- 规划预览可复现；
- 规划单元必须有关联来源和完成标准；
- 预览不能生成掌握结论；
- 站内通知读取、归档和邮件取消；
- SMTP 通过测试替身验证，不在 CI 发送真实邮件；
- 凭据不进入数据库原文、前端响应或日志；
- 桌面和移动学习面板；
- OpenAPI、TypeScript 契约和完整 `release-readiness` 无漂移。
