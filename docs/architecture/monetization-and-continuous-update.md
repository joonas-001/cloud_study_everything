# 第五里程碑：证据约束的变现准备与持续更新

> 状态：5A、5B 已合并并完成主线验证；5C 已于 2026-08-01 授权并按已确认边界实施
> 更新日期：2026-08-01
> 基线：`origin/main@ec9fdc0`，5C 实现分支 `codex/milestone-5c`
> 适用范围：本地单用户、算法技能、用户目标选择及就业/接单/产品化三路径
> 本文不构成：公开发布、云资源创建或自动投递/联系/交易等对外动作授权

## 1. 制定依据

第五里程碑服务于项目总闭环：

```text
诊断 → 学习 → 练习 → 项目 → 评估 → 复习 → 变现实验
```

当前已经具备的真实基础是：

- 第三里程碑已提供诊断、规划、来源元数据检查、通知和 AI 供应商档案；
- 第四里程碑 4A 已通过 PR #2 合并到 `main`，本地和合并后远程 CI 均成功；
- 4A 只覆盖 `algorithm@0.2.0` 共同主干入口的一条受限纵向切片；
- 4A 的自由文本、代码文本和用户自评只能形成有限证据，不能证明内容正确；
- 4A 不产生整体 `scope_criteria_met`、`verified` 代码能力或无限范围的掌握结论；
- 4B 已通过 PR #6 合并并完成本地真实 Runner 十项安全与资源限制验证；
- Runner 基础设施验证不能替代当前用户在精确能力范围内的 `verified`／`retained` 证据；
- 5B 已确认只使用 `deepseek-v4-flash`、中国大陆首版市场范围、官方一手来源和硬预算；
- 项目不得在证据不足时建议用户提供超出能力范围的服务，也不得保证工作、订单或收入。

因此，第五里程碑的成功不等于“立即开始赚钱”。它首先要可靠地区分：

1. 证据明确不足，应返回能力缺口；
2. 证据、来源或复核状态不足以判断，应返回待办；
3. 只有在明确范围和门禁内，才允许形成下一步建议。

当前真实 4A 数据很可能落入前两类。这是正确的安全结果，不是失败。

## 2. 已确认边界

项目所有者已经确认：

1. 先完成 4A PR 审查、合并和主线验证，再确认第五里程碑范围；该门禁已满足。
2. 允许无外部调用的 5A 先行。
3. 5B 必须等待以下四类决定全部确认：
   - 首批 AI 模型；
   - 目标市场范围；
   - 来源获取与更新方案；
   - 费用预算和停止条件。
4. 真实动作实验必须同时使用锁定的 4B Runner 证据和外部真人评审，不能二选一；
5. 4A 的文本提交、自评、结构校验和有限证据不能替代真实交付门禁。
6. 初次授权只包含 5A；项目所有者之后于 2026-07-29 单独授权 5B，并于
   2026-08-01 单独授权 5C；
7. 当前目标由用户运行时选择，可以是考试、纯学习、就业、接单、产品化或其他目标；
   系统不得默认用户希望变现。

“无外部调用的 5A”在本文中明确表示：

- 不调用外部 AI；
- 不访问市场 API、远程网页、RSS 或其他远程来源；
- 不发送邮件、消息或平台请求；
- 不创建云资源或付费资源；
- 不执行用户代码；
- 不上传文件，不读取用户任意本地路径；
- 只使用已有本地证据、版本化确定性规则和显著标记的合成市场快照。

本次工作已获 5A 业务代码实施授权。

## 3. 阶段拆分

### 3.1 5A：本地确定性准备度与比较底座

5A 建立契约、存储、证据门禁、合成市场快照和三路径比较，不进行任何外部调用。

它要证明两件事：

- 系统能够用可复现规则拒绝证据不足或无法判断的变现建议；
- 系统能够在合成夹具满足测试策略时走完比较流程，但不会把夹具当作真实市场事实。
- 系统能够对考试、纯学习和其他非变现目标返回“变现比较不适用”，而不是强制推荐求职。

5A 不证明真实市场存在需求，也不授权创建真实算法交付实验。

### 3.2 5B：真实市场研究与持续更新

5B 接入经确认的真实来源和 AI 供应商，维护新鲜度、冲突、失败和内容更新建议。

5B 的四项决定已经由项目所有者确认，当前只按以下范围实施：

- DeepSeek 官方 API 的 `deepseek-v4-flash`，不得切换其他模型或供应商；
- 中国大陆、中文为主，覆盖初级 C++ 后端、算法应用工程、中小客户接单及中文个人开发者/算法学习者；
- 只访问政府、监管、标准组织或数据所有方的一手官方公开来源；
- 月 ¥5、日 ¥0.50、单次 ¥0.20，禁止自动充值，官方价格变化或无法核验时停止。

### 3.3 5C：最小实验与学习回流

5C 负责用户确认后的本地实验计划、结果记录、复盘和学习回流建议。首版只启用中国大陆
中文市场的初级 C++ 后端与算法应用就业路径；接单和产品化继续保留通用契约，但明确禁用。

草稿允许在证据不足时存在。本地批准要求六维证据均存在且无阻断标记；记录真实求职动作
还要求操作维度至少 `verified`、保持维度为 `retained`、迁移与作品维度各有最新版外部
真人通过评审，并绑定同一目标、能力范围和精确技能包版本下当前已接受的市场研究。

## 4. 5A 可执行目标

### M5A-001：建立通用契约

新增版本化契约，至少覆盖：

- `user_goal`：用户当前选择的目标及其适用性；
- `readiness_policy`：准备度策略；
- `market_evidence_snapshot`：市场证据快照；
- `path_comparison`：就业、接单和产品化比较；
- `readiness_evaluation`：一次可复现评估；
- `decision_reason`：稳定原因码、证据引用和限制；
- `synthetic_fixture_metadata`：合成数据标记和用途。

契约必须：

- 使用稳定 ID 和语义版本；
- 明确适用技能、能力范围和路径；
- 引用精确技能包、策略、证据和快照版本；
- 区分事实、用户自述、推断、合成数据和未验证信息；
- 不把算法技能、单一招聘网站或接单平台硬编码进通用引擎；
- 不包含真实外部调用所需的未确认供应商参数。

验收证据：

- JSON Schema 校验通过；
- 正例、反例和跨字段约束测试通过；
- 契约进入本地检查、CI 和 `release-readiness`；
- OpenAPI 与生成的 TypeScript 制品无漂移。

### M5A-002：实现证据聚合与准备度门禁

准备度服务只读取已经持久化的本地数据：

- 明确能力范围；
- 六维证据等级；
- 人工复核、保持复核和来源复核标记；
- 证据时间；
- 技能包、规划和学习执行精确版本锁。

建议状态：

- `not_applicable`：用户当前选择的是考试、纯学习或其他非变现目标；
- `not_ready`：证据明确不足；
- `review_required`：存在阻断性复核、冲突或过期信息；
- `comparison_ready`：仅允许生成本地比较；
- `experiment_ready`：策略允许请求创建实验。

5A 对真实用户执行以下保守规则：

- 非变现目标不进入市场快照和三路径比较；
- 未确认真实阈值前，不输出真实用户 `experiment_ready`；
- 4A 完成状态不能代替六维证据；
- `limited` 或 `supported` 不能被提升为 `verified`；
- 待人工、保持或来源复核标记不能覆盖原证据，但可以阻断后续状态；
- 每次评估保存输入快照、策略版本、结果、原因码和时间；
- 相同输入和版本必须得到相同结果。

验收场景：

- 证据不足返回具体缺口；
- 待复核返回具体阻断项；
- 旧证据不被当作当前证据；
- 更正后的证据产生新评估，不改写旧评估；
- 当前 4A 真实记录不会获得真实算法交付资格。

### M5A-003：建立合成市场快照与三路径比较

5A 使用固定、显著标记的合成快照，不使用实时市场数据。

至少准备六类夹具：

1. 非变现目标，市场比较不适用；
2. 能力证据不足；
3. 市场快照过期；
4. 高质量来源冲突；
5. 关键结论无法验证；
6. 满足测试策略，可以生成三路径比较。

三条路径使用相同顶层维度：

- 当前能力证据匹配度；
- 缺少的能力、保持和作品证据；
- 合成市场需求证据及其新鲜度；
- 入门时间、成本和维护负担；
- 对外承诺和交付风险；
- 隐私、安全、平台、法律或税务待办；
- 可逆性和失败成本；
- 当前不确定性。

比较结果允许：

- 一条路径更适合作为下一步研究对象；
- 多条路径接近，由用户决定；
- 三条路径均不适合当前启动；
- 证据不足，不作推荐。

不得：

- 用任意总分掩盖路径差异；
- 把合成职位数、价格或需求包装成真实市场事实；
- 保证工作、订单、收入或投资回报；
- 从比较结果直接创建可对外执行的实验。

### M5A-004：建立不可变存储和审计

通过 SQLAlchemy 2 和 Alembic 新增版本化存储，至少支持：

- 准备度策略版本；

约束：

- 已保存评估和比较不得原地重算或覆盖；
- 新策略产生新记录；
- 不修改 `algorithm@0.2.0` manifest 或受管内容；
- 不改写 4A 的活动、attempt、证据或审计历史；

迁移必须覆盖：

- 空数据库升级；
- 现有 4A 数据库升级；
- 可支持的降级；
- 唯一约束、外键和状态约束；
- 旧记录在策略升级后仍可复现。

### 5B 运行时完整性约束

- 版本化市场研究注册表把技能实例映射到受管来源目录和预算策略；核心服务不固定算法主题或文件路径；
- 每次研究锁定技能 ID、精确技能包版本、能力范围、当前用户目标、可选准备度评估、
  来源目录与预算策略的 ID、版本、摘要和完整快照；上下文不匹配时拒绝继续；
- 原始 HTTP 响应、完整规范化正文和最多 2000 字符的外发摘录分别保存哈希；原始模板变化
  与正文变化分开记录，短摘录哈希不得代表整页变化；
- 每条路径显式声明 `conclusive_supported` 或 `context_only` 证据能力。当前首版目录三条路径
  都是 `context_only`：它覆盖已确认的研究范围，但不具备目标岗位、接单需求或产品需求的
  合格直接信号，因此确定性返回 `indeterminate`；
- 付费综合通过 SQLite 原子写事务抢占 `synthesis_in_progress`，并在调用前计入最坏费用预留；
- 同一研究只能有一个持久化综合 attempt；`claimed`、`dispatch_started`、
  `response_received`、`accounted` 阶段以追加审计事件留痕；
- attempt 使用锁定预算中的 5 分钟租约。启动或读取概览时发现过期调用会进入
  `recovery_required`，不会重试；已开始发送但收费未知时按最坏费用保守记账，用户可显式
  确认结束并保留审计；
- DeepSeek 请求由独立适配器构造，业务服务不直接拼装供应商 HTTP 请求；
- 外发前以请求 UTF-8 字节数作为保守 token 上界，超过 50,000 时不发送；
- 当目录中三条路径都只有 `context_only` 能力时，请求采用
  `limited_background_v1`：模型只能返回逐路径背景摘要、来源 ID、不确定性和整体限制，
  不能返回路径状态、内容影响建议、收入判断或外部行动。后端确定性把所有路径固定为
  `indeterminate`，把内容影响固定为 `no_change`；
- 响应依次经过 HTTP/类型、响应模型、usage、内容提取、JSON、受限协议和后端规范化结构
  校验。无效内容审计不保存原文、未知键名或未知值，只保存协议、失败阶段、受管键识别、
  缺失键、未知键数量、校验类别、内容长度/哈希及已知 token/费用；
- 只要响应 usage 可验证，即使内容校验失败也必须保存实际 token 和计算费用；已经
  dispatch 的失败不得按预派发失败恢复，也不得自动重试；
- 后端以同一份净化材料结构生成界面预览和最终综合请求；用户在逐次确认前可以检查来源
  ID、所有者、适用路径、限制和实际短摘录，并清楚看到会发送与不会发送的数据类别；
- 用户可以在界面逐项确认删除已保存摘录。删除会重新计算可用材料，并使依赖该摘录的
  待复核或历史综合显式失效；删除事件只保存来源 ID、原因和哈希保留情况；
- 请求模型与响应声明模型分别保存和展示；缺失、超长或不等于
  `deepseek-v4-flash` 的响应模型不得进入人工接受流程，且因费用无法可靠估计而按单次
  研究硬上限保守记账；
- `supported` 和 `conflicted` 必须由目录声明该路径具备确定性证据能力，并引用至少两个
  本次成功获取、来自不同 `independence_group` 的来源；其中至少一个必须是本次正文中
  实际出现目标可观察信号的直接来源。只有宏观背景、同机构双页面或内容不相关时必须返回
  `indeterminate`；
- 官方入口页可以作为背景，但不得被描述为具体岗位、订单、客户预算或个人产品需求的直接证明；
- 来源撤回会阻止进行中的删除，并使待复核或历史综合显式失效；历史输出和事件继续保留用于审计；
- 受管来源目录 `1.2.0` 分开记录逐来源最近访问 attempt 和最近成功快照；成功访问后 7 天
  才可再次访问，失败后冷却 24 小时，首版没有人工绕过。部分来源失败时，冷却结束后只访问
  已到期来源，仍在成功刷新窗口内的来源复用既有快照；
- 官方价格必须从同一 HTML 表格的 `deepseek-v4-flash` 列逐项核对，其他模型或历史数字不能替代；
  价格表可能使用 `rowspan` 增加“价格”等分组列，解析器必须先定位价格标签，再按模型在表头中的
  相对顺序读取相邻价格，禁止假设所有行使用固定绝对列号；
- `pricing_changed_or_unverifiable` 只有在没有 synthesis attempt、没有 dispatch/响应证据、
  token 与实际/记账费用均为 0、外发材料仍不少于两个时，才能经独立显式确认恢复到
  `synthesis_pending`。恢复事件保留原失败码且不调用模型；之后仍需单独确认外部 AI 发送；
- 会改变后端状态的失败响应返回后，界面保留原错误并重新加载概览和审计历史；请求未到达
  后端的网络失败不伪装成已刷新状态；
- API 和界面可以查看最近研究及经过净化的审计事件，事件不保存密钥或完整外发材料；
- Playwright 使用独立离线测试宿主：官方页面、价格页、凭据和模型响应全部为内存替身。
  桌面流程覆盖外发预览、付费综合、人工接受、摘录删除和综合失效；移动流程覆盖响应模型
  不一致、保守记账和失败后原页面状态刷新。测试宿主不访问真实来源或 DeepSeek。

## 7. 5C 目标与实验门禁

5C 的本地实验记录模型包括：

- 明确能力范围和目标受众；
- 选择路径的证据和缺口；
- 单一、可观察的假设；
- 时间、成本和停止条件；
- 用户准备自行执行的动作；
- 不会提供的服务或功能；
- 平台、法律、税务、隐私和版权待办；
- 可观察结果和复盘日期；
- 所用策略、市场快照和技能包版本。

已确认状态：

```text
draft
├── 用户拒绝 ───────────────> rejected
├── 门禁失效 ───────────────> blocked
└── 用户明确确认 ───────────> approved
                              │
                              ▼
                            active
                 ├── 暂停 ──> paused ──> active
                 ├── 停止 ──> ended
                 └── 完成 ──> completed
```

- `approved` 不等于外部平台已经执行；
- `completed` 只表示实验结束，不表示获得收入；
- 终态和全部历史必须保留；
- 门禁失效时进入 `blocked` 或 `paused`；
- 恢复前重新评估证据、市场新鲜度并记录用户确认。

门禁分为两级：

1. `local_ready`：六维证据均至少有一项，且不存在策略列出的来源、保持、人工复核等阻断
   标记；允许用户审阅和批准本地计划。
2. `action_ready`：在 `local_ready` 基础上，90 天内的操作维度至少为 `verified`，
   保持维度为 `retained`；迁移与作品维度各自在 90 天内的外部真人评审必须精确绑定
   当前能力范围并使用受管量表，且绑定同一目标、精确技能包 manifest 和 7 天内已接受的
   同上下文市场研究。任何未来日期无效。

外部真人评审只保存评审者与用户的关系、受管能力范围 ID、量表及版本、结论和时间，不保存
身份证明或敏感附件。用户自评、AI 评审、自由文本范围、未注册量表、文本长度、结构校验、
单次简单测验或课程完成状态均不能替代。

产品只生成本地计划、核对清单和文案草稿，并记录用户已在产品外手动完成的动作。它不得登录
外部平台，不得自动投递、联系、发布、签约、收款或交易。每次动作记录都要求用户明确确认其
已在产品外完成；版本、来源、目标或证据失效时，活动实验进入阻断或暂停。

收入记录为可选本地记录，金额默认隐藏且不保存附件。记录包括币种、总额口径、平台费、直接
成本、实收金额、日期和核验状态；修订只追加，JSON/CSV 导出必须显式确认。隐私删除会清除
敏感值并保留不含金额的审计墓碑。收入绝不反推掌握程度，也不用于保证未来收入。

匹配，但内容未通过原 JSON／业务结构校验，因此没有形成可采纳综合；系统没有重试或切换
模型，按可验证 usage 保守计入 ¥0.003597。

该失败推动 `limited_background_v1` 与隐私安全分阶段诊断：后端而非模型固定
