# 第五里程碑：证据约束的变现准备与持续更新

> 状态：阶段边界已确认，详细目标已落档
> 更新日期：2026-07-29
> 基线：`main@953d2d2`，GitHub Actions 运行 `30420229605` 全部成功
> 适用范围：本地单用户、算法技能、就业/接单/产品化三路径
> 本文不构成：5B 授权、4B 授权、付费资源授权、公开发布或对外动作授权

## 1. 制定依据

第五里程碑服务于项目总闭环：

```text
诊断 → 学习 → 练习 → 项目 → 评估 → 复习 → 变现实验
```

当前已经具备的真实基础是：

- 第三里程碑已提供诊断、规划、来源元数据检查、通知和 AI 供应商档案；
- 第四里程碑 4A 已通过 PR #2 合并到 `main`，本地和合并后远程 CI 均成功；
- 4A 只覆盖 `algorithm@0.2.0` 共同主干入口的一条受限纵向切片；
- 4A 的自由文本、代码文本和用户自评只能形成有限证据，不能证明内容正确；
- 4A 不产生整体 `scope_criteria_met`、`verified` 代码能力或无限范围的掌握结论；
- 4B 隔离代码运行仍未授权，产品当前不得执行用户代码；
- 首批真实 AI 模型、目标市场、来源获取方案和 5B 预算仍未确认；
- 项目不得在证据不足时建议用户提供超出能力范围的服务，也不得保证工作、订单或收入。

因此，第五里程碑的成功不等于“立即开始赚钱”。它首先要可靠地区分：

1. 证据明确不足，应返回能力缺口；
2. 证据、来源或复核状态不足以判断，应返回待办；
3. 只有在明确范围和门禁内，才允许形成下一步建议。

当前真实 4A 数据很可能落入前两类。这是正确的安全结果，不是失败。

## 2. 已确认边界

项目所有者已经确认：

1. 先完成 4A PR 审查、合并和主线验证，再确认第五里程碑范围；该门禁已满足。
2. 允许无外部调用的 5A 先行。
3. 5B 必须等待以下四类决定全部确认：
   - 首批 AI 模型；
   - 目标市场范围；
   - 来源获取与更新方案；
   - 费用预算和停止条件。
4. 真实算法交付类实验必须等待：
   - 经单独授权的 4B；或
   - 项目所有者确认的其他独立验证证据。
5. 4A 的文本提交、自评、结构校验和有限证据不能替代真实交付门禁。

“无外部调用的 5A”在本文中明确表示：

- 不调用外部 AI；
- 不访问市场 API、远程网页、RSS 或其他远程来源；
- 不发送邮件、消息或平台请求；
- 不创建云资源或付费资源；
- 不执行用户代码；
- 不上传文件，不读取用户任意本地路径；
- 只使用已有本地证据、版本化确定性规则和显著标记的合成市场快照。

本次工作只确认并落档目标，不开始 5A 业务代码实施。

## 3. 阶段拆分

### 3.1 5A：本地确定性准备度与比较底座

5A 建立契约、存储、证据门禁、合成市场快照和三路径比较，不进行任何外部调用。

它要证明两件事：

- 系统能够用可复现规则拒绝证据不足或无法判断的变现建议；
- 系统能够在合成夹具满足测试策略时走完比较流程，但不会把夹具当作真实市场事实。

5A 不证明真实市场存在需求，也不授权创建真实算法交付实验。

### 3.2 5B：真实市场研究与持续更新

5B 接入经确认的真实来源和 AI 供应商，维护新鲜度、冲突、失败和内容更新建议。

5B 当前为阻塞状态。`AI-001`、`MARKET-001`、`CONTENT-001`、
`BUDGET-001` 任一未完成，都不得开始真实调用。

### 3.3 5C：最小实验与学习回流

5C 负责用户确认后的本地实验计划、结果记录、复盘和学习回流建议。

5C 的首个重点路径、最低证据、外部动作边界和收入记录策略仍待确认。真实算法交付类实验
额外受 4B 或独立验证证据门禁约束。

## 4. 5A 可执行目标

### M5A-001：建立通用契约

新增版本化契约，至少覆盖：

- `readiness_policy`：准备度策略；
- `market_evidence_snapshot`：市场证据快照；
- `path_comparison`：就业、接单和产品化比较；
- `readiness_evaluation`：一次可复现评估；
- `decision_reason`：稳定原因码、证据引用和限制；
- `synthetic_fixture_metadata`：合成数据标记和用途。

契约必须：

- 使用稳定 ID 和语义版本；
- 明确适用技能、能力范围和路径；
- 引用精确技能包、策略、证据和快照版本；
- 区分事实、用户自述、推断、合成数据和未验证信息；
- 不把算法技能、单一招聘网站或接单平台硬编码进通用引擎；
- 不包含真实外部调用所需的未确认供应商参数。

验收证据：

- JSON Schema 校验通过；
- 正例、反例和跨字段约束测试通过；
- 契约进入本地检查、CI 和 `release-readiness`；
- OpenAPI 与生成的 TypeScript 制品无漂移。

### M5A-002：实现证据聚合与准备度门禁

准备度服务只读取已经持久化的本地数据：

- 明确能力范围；
- 六维证据等级；
- 人工复核、保持复核和来源复核标记；
- 证据时间；
- 技能包、规划和学习执行精确版本锁。

建议状态：

- `not_ready`：证据明确不足；
- `review_required`：存在阻断性复核、冲突或过期信息；
- `comparison_ready`：仅允许生成本地比较；
- `experiment_ready`：策略允许请求创建实验。

5A 对真实用户执行以下保守规则：

- 未确认真实阈值前，不输出真实用户 `experiment_ready`；
- 4A 完成状态不能代替六维证据；
- `limited` 或 `supported` 不能被提升为 `verified`；
- 待人工、保持或来源复核标记不能覆盖原证据，但可以阻断后续状态；
- 每次评估保存输入快照、策略版本、结果、原因码和时间；
- 相同输入和版本必须得到相同结果。

验收场景：

- 证据不足返回具体缺口；
- 待复核返回具体阻断项；
- 旧证据不被当作当前证据；
- 更正后的证据产生新评估，不改写旧评估；
- 当前 4A 真实记录不会获得真实算法交付资格。

### M5A-003：建立合成市场快照与三路径比较

5A 使用固定、显著标记的合成快照，不使用实时市场数据。

至少准备五类夹具：

1. 能力证据不足；
2. 市场快照过期；
3. 高质量来源冲突；
4. 关键结论无法验证；
5. 满足测试策略，可以生成三路径比较。

三条路径使用相同顶层维度：

- 当前能力证据匹配度；
- 缺少的能力、保持和作品证据；
- 合成市场需求证据及其新鲜度；
- 入门时间、成本和维护负担；
- 对外承诺和交付风险；
- 隐私、安全、平台、法律或税务待办；
- 可逆性和失败成本；
- 当前不确定性。

比较结果允许：

- 一条路径更适合作为下一步研究对象；
- 多条路径接近，由用户决定；
- 三条路径均不适合当前启动；
- 证据不足，不作推荐。

不得：

- 用任意总分掩盖路径差异；
- 把合成职位数、价格或需求包装成真实市场事实；
- 保证工作、订单、收入或投资回报；
- 从比较结果直接创建可对外执行的实验。

### M5A-004：建立不可变存储和审计

通过 SQLAlchemy 2 和 Alembic 新增版本化存储，至少支持：

- 准备度策略版本；
- 合成市场快照和结构化事实；
- 证据引用与冲突；
- 准备度评估快照；
- 三路径比较快照；
- 用户对比较的接受、拒绝或延后；
- 完整审计事件。

约束：

- 应用启动不得使用 `create_all`；
- 已保存评估和比较不得原地重算或覆盖；
- 新策略产生新记录；
- 不修改 `algorithm@0.2.0` manifest 或受管内容；
- 不改写 4A 的活动、attempt、证据或审计历史；
- SQLite 数据文件和测试数据库不得提交。

迁移必须覆盖：

- 空数据库升级；
- 现有 4A 数据库升级；
- 可支持的降级；
- 唯一约束、外键和状态约束；
- 旧记录在策略升级后仍可复现。

所有写接口必须验证：

界面至少展示：

- 当前能力范围；

- 准备度状态、原因码和下一项缺口；
- 就业、接单、产品化并列比较；

- “不保证工作、订单或收入”的持续提示；

必须验证：

## 7. 5C 目标与实验门禁

5C 的本地实验记录模型建议包括：

- 明确能力范围和目标受众；
- 选择路径的证据和缺口；
- 单一、可观察的假设；
- 时间、成本和停止条件；
- 用户准备自行执行的动作；
- 不会提供的服务或功能；
- 平台、法律、税务、隐私和版权待办；
- 可观察结果和复盘日期；
- 所用策略、市场快照和技能包版本。

建议状态：

```text
draft
├── 用户拒绝 ───────────────> rejected
├── 门禁失效 ───────────────> blocked
└── 用户明确确认 ───────────> approved
                              │
                              ▼
                            active
                 ├── 暂停 ──> paused ──> active
                 ├── 停止 ──> ended
                 └── 完成 ──> completed
```

- `approved` 不等于外部平台已经执行；
- `completed` 只表示实验结束，不表示获得收入；
- 终态和全部历史必须保留；
- 门禁失效时进入 `blocked` 或 `paused`；
- 恢复前重新评估证据、市场新鲜度并记录用户确认。

真实算法交付类实验只能在以下任一条件满足后进入可执行状态：

1. 4B 经单独授权、实施并产生相称验证证据；或
2. 项目所有者确认其他独立验证流程及其证据。

“其他独立验证证据”的具体形式尚未决定。实施者不得自行把用户自评、AI 自评、文本长度、
结构校验、单次简单测验或课程完成状态定义为独立验证。

## 8. 学习与内容更新回流

实验或市场研究发现的缺口只能形成待确认建议：

- 新诊断问题；
- 纠错、复习或项目任务；
- 补充学习单元；
- 重新规划；
- 市场来源复核；
- 暂停某条路径。

建议必须说明原因、证据、预计工作量和计划影响。用户确认前不得：

- 修改现有规划；
- 覆盖已有证据；
- 修改已锁定技能包；
- 自动插入补充单元；
- 自动迁移学习执行。

来源或教学内容变化需要发布新技能包版本。`algorithm@0.2.0` 保持不可变。

6. 完成失败、冲突、删除和费用停止场景；
7. 通过本地和远程验证。

### 5C

只有实验范围和证据门禁确认后，另立实施任务。真实算法交付路径不得绕过 4B 或独立验证证据。

## 11. 阶段完成标准

### 5A 完成

只有同时满足以下条件才能称 5A 完成：

- 契约、迁移、确定性服务、API 和界面形成一条本地纵向切片；
- 当前 4A 真实证据不会被提升为真实交付资格；
- 合成夹具显著标记且不能泄漏为真实市场事实；
- 三路径可以比较，也允许三条均不适合；
- 所有结果保留策略、证据、快照和版本依据；
- 没有外部网络、AI、对外动作、代码执行、文件上传或任意路径读取；
- 桌面、移动、空、加载、错误和阻断状态通过验证；
- 完整本地 `release-readiness` 和远程 CI 成功；
- 文档清楚说明 5B、5C 和 4B 仍未实现的能力。

### 5B 完成

需要真实来源和模型在已确认预算内形成可审计闭环，且来源失败、过期和冲突不会被静默忽略。

### 5C 完成

需要用户确认的实验状态机、可观察结果和学习回流闭环通过验证；真实交付路径必须满足独立证据门禁。

第五里程碑整体完成不表示用户已经具备就业、接单或产品化能力，也不表示已经获得工作、订单或收入。

## 12. 仍待确认

以下决定仍会实质影响产品行为、成本、隐私或返工：

2. 目标市场的地区、语言、岗位、平台/客户和受众；
3. 来源获取、索引、更新、删除和版权方案；
