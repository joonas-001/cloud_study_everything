作为开放入口，`0.3.0` 仍是 `draft + intake: closed`。

## 2. 确定性规则

- 只从精确技能包的诊断题、能力 DAG 和诊断策略读取受管元数据；不使用模型记忆或外部调用；
- 选题依次比较下游阻断度、区分补救与继续的价值、重复次数和稳定题目 ID；
- 单能力至少两个不同题目的确定性正向信号且前置无补救时为 `ready`；受管关键错误为
  `remediation_required`；跳过、不确定、非确定性或信号不足保持 `inconclusive`；
- 修正答案后从全部最新修订重算，前置进入补救时下游明确保持不确定，不静默解锁；
- 正常排序失败时回退受管固定序列并记录原因；同一规范化答案状态生成相同 SHA-256、状态和
  下一题；
- 达到 36 题、50 分钟、完成分类或用户主动结束时停止。未充分覆盖的能力不会被猜测；
- 每次决定写入追加式审计事件。恢复时重新计算并比对摘要与下一题；未来时间、未知引用、
  缺失／损坏审计或不一致的持久化状态会被拒绝。

诊断输出的证据上限固定为 `diagnostic_signal_only`。它不能产生 `supported`、`verified`、
`retained`，也不能表示整门算法掌握、分支解锁或真实交付资格。

## 3. API 和界面

诊断响应新增兼容字段：诊断模式、当前决定、题量／时间预算、46 项范围化能力状态，以及当前
问题的选择原因码和解释。旧版本返回 `fixed_sequence`、空决定和空能力状态，原客户端行为不变。

诊断界面在未来收到自适应会话时展示可重放标记、选择依据、预算使用、三态数量和证据限制；
当前页面仍创建 `algorithm@0.2.2` 预览，不提供 0.3.0 开关。API 负向测试也明确验证 0.3.0
创建请求继续因 `skill_package_intake_closed` 被拒绝。

## 4. 验证范围和限制

自动测试覆盖固定序列回归、相同状态重放、进程重启恢复、正向双信号、关键错误、修正后的
下游重算、题量停止、时间停止、规则失败回退、持久化篡改拒绝、未来时间拒绝和关闭入口。
完整本地 `release-readiness` 覆盖后端、前端、生产构建、桌面／移动／平板／WebKit E2E、
技能包治理、契约无漂移和密钥扫描。最终结果为 126 项后端通过、1 项按预期跳过、43 项前端
通过、生产构建成功、22 项 E2E 通过、6 项按范围跳过，契约无漂移且密钥扫描成功。

首次完整门禁在 WebKit 长时重复导航末尾发现随机 Web/API 端口间已取消请求被报告为访问控制
错误。隔离 E2E 随后改为与生产一致的同源 `/api` rewrite；测试进程仍只在服务端以精确地址
直连 API 做数据准备。修复后全部 E2E 通过，且没有放宽生产 CORS、CSP 或身份边界。

本次没有创建真实 0.3.0 诊断记录、执行学习者代码、访问远程来源、运行真实 Runner、调用
外部 AI、安装依赖、改变本地服务或云端。8B 的来源实质复核、强制第二评审和锁定镜像 Runner
全量复验仍是显式待办，不能被 8C 引擎测试覆盖。
