## 1. 授权和边界

项目所有者于 2026-08-30 单独授权 8D。实现只覆盖共同主干学习执行、每日重排、
范围化证据、固定延迟复习、十二域阶段检查和四分支准确门禁。该授权不包含 8E–8G、
默认入口切换、远程来源实质复核、外部 AI、真实 Runner 全量复验、GitHub 远程写操作、
云端变更或公开发布。

本地测试通过临时数据库和合成记录验证 `algorithm@0.3.0`。没有在真实库创建该版本的
诊断、规划、学习或证据记录；注册表仍以 `0.2.2` 作为开放入口。

## 2. 实现结果

- 每日预算默认 120 分钟；超过预算必须对当天明确确认并记录原因；
- 共同主干按“到期保持、失败纠错、阻断前置、新内容”稳定排序，同日不堆叠多个高负荷新域；
- 预算或认知负荷导致的任务以追加式原因延期，不产生能力失败；
- 学习执行支持带原因暂停、恢复和完整事件审计；显式结束仍不可恢复；
- 十二域阶段检查只报告初轮流程进度，不声称领域或整门算法掌握；
- 确定性结构检查最多形成精确能力范围的 `supported`；
- C++／Python 只有在锁定 Runner 结果协议独立校验通过后，才形成同任务范围的
  `verified`；只有到期的同语言、同任务和同运行时复测通过才形成 `retained`；
- 迁移、解释和作品文本通过结构校验后可以继续，但未经真人评审不声称技术内容正确；
- 外部真人评审只保存关系、精确能力和活动范围、受管量表、结论与日期，拒绝未来日期和
  空白关系，不保存身份证明或附件，最长有效 90 天；
- 四分支门禁分别显示满足、过期、未来无效、缺失、保持缺口和待复核项，不自动选择分支，
  也不因执行 `completed`、基础设施探针、自评或 AI 评价而解锁。

Alembic `0011` 增加 `paused` 状态、范围和语言证据字段及真人评审表。升级、降级、
备份恢复和部署预检均已同步到当前迁移头。历史 `0.1.0`–`0.2.2` 内容文件未修改；
旧版每日任务继续保留原有稳定顺序，8D 新重排只作用于声明四分支门禁的共同主干包。

## 3. API 和界面

OpenAPI 和 TypeScript 契约新增今日超时确认、延期任务、暂停／恢复、十二域阶段检查、
真人评审和四分支门禁响应。学习工作区展示任务优先级、延期原因、范围和语言证据上限、
暂停恢复、阶段检查、受管真人评审表单及门禁缺口。

客户端先读取阶段检查；只有精确版本实际声明共同主干时才请求分支门禁，因此当前
`0.2.2` 页面不会误用 8D 契约，也不会出现 `0.3.0` 入口。

## 4. 验证结果

- 后端：129 项通过，1 项因 Windows 文件权限按预期跳过；
- 前端：44 项 Vitest 通过，TypeScript 与 ESLint 通过；

- E2E：Chromium 桌面、移动、平板与 WebKit 共 22 项通过，6 项按既定范围跳过；
- Ruff、mypy、迁移、备份恢复、部署预检、旧版执行和 Runner 协议回归通过；
- 注册表、manifest、来源、规划、学习内容、评估、复习、掌握、Runner、安全、
  外部调用、部署、契约与密钥扫描通过，生成契约无漂移。
